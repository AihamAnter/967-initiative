# إدارة حسابات مستخدمي 967

الصفحة: `/admin/users`، وتظهر فقط لحسابات `management` في جدول `public.editors`. دور `admin` التحريري لا يمكنه الاطلاع عليها.

## البيانات والأعمال المتاحة
- الاسم، البريد الإلكتروني، تاريخ إنشاء الحساب، آخر دخول، حالة التأكيد والحظر، وطريقة الدخول والدور.
- البحث والفلترة والترتيب مع عرض 25 حسابًا بكل صفحة.
- حظر حساب مستخدم أو رفع حظره وفق القواعد السابقة. لا يمكن حظر حساب إداري.
- زر **مراسلة** يفتح نظام المراسلة الخاص بالموقع على `/messages?to=<user_id>`. يفتح محادثة قائمة، أو ينشئ طلب محادثة أولًا إذا لم تكن موجودة.
- **لم يعد زر مراسلة يُرسل بريدًا إلكترونيًا، ولا يحتاج Resend.** لا تحصل الإدارة على استثناء من موافقة المستلم أو حظره أو إعداد تعطيل استقبال الطلبات.

## الخصوصية
- التحقق من الدور في API والخادم إلزامي؛ عرض الزر وحده ليس آلية حماية.
- يجوز للإدارة معرفة حسابات مستخدمي 967 عبر لوحة الإدارة، حتى إن عطّل أحد المستخدمين الظهور في بحث الرسائل. لكن مراسلته تظل مرهونة بإعداد استقبال الطلبات ونظام موافقة المحادثة.
- لا تتيح لوحة المستخدمين قراءة المحادثات الخاصة. الاطلاع على نصوص محادثة مبلّغ عنها يتم فقط من `/admin/message-reports`، داخل سياق البلاغ الفعلي، ويُسجَّل كل اطلاع في سجل مستقل.
- معرّفات الرسائل وروابط المحادثة لا تمنح أي صلاحية إضافية.

## التحقق
1. تسجيل الدخول بحساب إدارة والتأكد من ظهور الرابط إلى المحادثة الداخلية.
2. فتح مستخدم له محادثة قائمة يوجه إلى المحادثة نفسها، وفتح مستخدم جديد يظهر طلب المحادثة.
3. طلب المحادثة يجب أن يخضع لقبول الطرف الآخر، وحدود 5 طلبات يوميًا والحظر الشخصي.
4. `admin` التحريري والمستخدم العادي يجب أن يُرفضا عند استخدام دليل الإدارة أو رابط الاتصال الإداري المباشر.
5. جرّب حسابًا معطّل استقبال طلبات المحادثة؛ ينبغي أن يفشل الطلب دون فتح أي محادثة.
