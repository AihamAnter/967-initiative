## معالجة التكرار والتحقق

- التعليم: جرى التطبيع للمقارنة فقط (الهمزات، التاء المربوطة، المسافات) مع بقاء الاسم الأصلي للعرض. مفتاح السجل مركب من المصدر والهوية؛ لم يبق أي تكرار في الاسم المطبّع مع المحافظة داخل الناتج النهائي.
- الصحة: الكود الرسمي لوزارة الصحة هو مفتاح الهوية، وتُدمج الصفوف المتكررة بالكود قبل أخذ العينة.
- يتحقق مولّد البيانات وأداة الاستيراد من تفرد `stable_key` و`slug` ووجود اسم ومصدر.
- لا تستبدل المطابقة التقريبية المصدر الرسمي؛ استُخدمت فقط لإضافة موقع أو نوع ملكية من الدليل المستقل، مع حفظ المصدرين داخل السجل.

## تعليمات الاستيراد

1. راجع `supabase/migrations/202610250007_institution_directories.sql` وطبّقه أولًا في مشروع Supabase معزول.
2. شغّل الاختبار المعزول: `node --test tests/institution-directory-database.test.mjs`.
3. شغّل المحاكاة: `npm run data:directories -- --kind=all`.
4. راجع كل سجل قبل النشر. الاستيراد الفعلي يحول السجلات إلى مسودات افتراضيًا، ويتجاوز أي `stable_key` موجود دون تعديله.
5. للاستيراد الفعلي فقط، اضبط متغيرات Supabase الآمنة ومتغير `DIRECTORY_IMPORT_CONFIRM=I_UNDERSTAND_THIS_WRITES_DIRECTORY_DATA` ثم أضف `--apply`.
6. لا تستخدم `--update-existing` إلا بعد مراجعة الفرق؛ ولا تستخدم `--preserve-publication` إلا بعد المراجعة التحريرية وضبط `DIRECTORY_PUBLISH_CONFIRM=I_REVIEWED_DIRECTORY_PUBLICATION`.

كل سجل يُحفظ مع علاقاته في معاملة ذرية مستقلة. فشل سجل لا يفسد سجلًا آخر، وتخرج الأداة بقائمة دقيقة للإخفاقات وبحالة فشل يمكن إعادة تشغيلها بأمان.
