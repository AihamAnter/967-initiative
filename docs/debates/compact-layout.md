# تبسيط صفحة المناظرة وساحة النقاش

التاريخ: 21 أكتوبر 2026. التغييرات محلية على الفرع `feat/debates-platform`، ولم تُنشر. تعديل العرض هذا لا يحتاج SQL جديداً؛ إعداد النتائج المباشرة السابق موثق في [دليل النتائج المباشرة](live-results.md).

## ما تغيّر

| طلب المستخدم | التنفيذ |
| --- | --- |
| تصغير العنوان | عنوان بحجم 23 بكسل على الهاتف وحتى 32 بكسل على الحاسوب، مع ترويسة مختصرة. |
| تقديم الفيديو | التسجيل هو أول محتوى بعد العنوان، وتبدأ مساحته ضمن الشاشة الأولى في المقاسات الستة المختبرة. البث الخارجي يعرض رابط الدخول وحالة المناظرة الفعلية في الموضع نفسه. |
| تبسيط المشاركين | بطاقات صغيرة تجمع الاسم والدور والموقف؛ يمكن فتح الموقف الطويل لقراءته كاملاً. |
| طي وصف القضية ومحاورها | قسمان مغلقان مبدئياً، يفتح كل منهما بالنقر أو لوحة المفاتيح. يستخدم القسم المفتوح عرض الهاتف كاملاً. |
| طي الملخص | قسم مستقل قابل للفتح والإغلاق. |
| تبسيط استطلاعي قبل وبعد | قسم واحد قابل للطي، بخطوتين واضحتين وخيارات كبيرة، ومواعيد اختيارية العرض. تتغير تسمية المرحلة بحسب كون المناظرة مسجلة أو مباشرة. |
| طي النتائج | قسم قابل للطي مع بقاء تحديث البيانات تلقائياً، حتى عندما يكون القسم مغلقاً. |
| توحيد الأسئلة والتعليقات | «ساحة النقاش» تجمع محرر المشاركة وقائمة موحدة بتصميم بطاقات، مع اختيار تعليق أو سؤال وفلاتر الكل والتعليقات والأسئلة ومشاركاتي. |

تحتفظ الساحة بتوجيه السؤال إلى مشارك ومحور، والنشر باسم «مشارك»، والرد على التعليقات والإبلاغ عنها وتعديل المالك وحذفه، وحالات المراجعة والصفحات والترتيب. تبقى مسودات السؤال والتعليق والتعديل محفوظة عند تغيير النوع أو الفلتر. لم تتغير صلاحيات قاعدة البيانات أو شروط اعتماد المشاركات. تستخدم القائمة واجهتي القراءة القائمتين وتجمع صفحاتهما دون تكرار أو فقد المشاركات.

تفتح الروابط القديمة للأسئلة والتصويت القسم المناسب تلقائياً. يعتمد الطي على عناصر `details` و`summary` الأصلية، ولا يغلق تحديث النتائج قسماً فتحه المستخدم. يبقى تحميل مشغل الفيديو مؤجلاً حتى طلب التشغيل، وتعمل روابط الفصول. تعكس حالات التأجيل والإلغاء حالتها الصحيحة عند عدم وجود تسجيل.

## التحقق

- نجح `npm.cmd test`: **149 اختباراً**، بما فيها قواعد البيانات والصلاحيات والنتائج.
- نجح فحص التنسيق البرمجي: صفر أخطاء، وثلاثة تحذيرات سابقة عن صور HTML في `MediaViewer.jsx` و`PdfReader.jsx`.
- نجح بناء Next.js للإنتاج في مجلد التحقق المنفصل.
- نجحت **12 حالة متصفح مخصصة للتصميم الجديد**: وضع الفيديو، الطي ولوحة المفاتيح، التشغيل والفصول، اكتمال 80 مشاركة، سباق استجابات الترتيب، صفحات المالك، المسودات والأسئلة الموجهة والمجهولة، التصويت، التعديل والرد والإبلاغ والحذف، وحالات المناظرة والروابط القديمة.
- فُحص العرض عند 320 و390 و430 و768 و1440 و1920 بكسل؛ دون تمرير أفقي غير مقصود. لم يرصد axe مخالفات WCAG 2 A/AA و2.1 AA في الساحة المفتوحة، ولم ترصد أخطاء JavaScript أثناء الاختبار.
- نجحت الرحلات الأساسية الـ12 مجدداً، وفحوص العرض الـ30، وفحوص axe للواجهات الست. نجحت أيضاً مجموعات التحقق من الحقول الست، وعزل النماذج السبع، وانحدار المراجعة الأربع.
- نجحت حالات النتائج المباشرة الثماني مع الأقسام الجديدة، بما فيها تحديث زائر آخر وتعديل التصويت والاتصال البديل وإخفاء النتائج واستعادتها والطلب البطيء.

الاختبارات استخدمت Next.js وواجهات API الحقيقية مع PostgreSQL محلي معزول عبر PGlite. حُوكي مشغل الفيديو وبروتوكول Realtime أثناء الاختبار؛ لم يختبر تشغيل فيديو خارجي فعلي أو اتصال مشروع Supabase المنشور. لم تُعدّل قاعدة الإنتاج.
