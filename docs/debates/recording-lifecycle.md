# دورة نشر التسجيل والأسئلة والاستطلاع الموحد

> **تنبيه بتاريخ 26 أكتوبر 2026:** ملفات SQL ذات التواريخ القديمة المذكورة هنا موجودة في أرشيف للرجوع إليها وللاختبارات التاريخية؛ ليست ترحيلات نشطة، ولا تُشغَّل على إنتاج 967. الـBaseline الحالي المرشح هو `supabase/migrations/20261026215718_remote_schema.sql` ولم تُسوَّ حالته في سجل الإنتاج بعد.

22 أكتوبر 2026. تم تنفيذ التحديث واختبار واجهة React وAPI ودوال PostgreSQL في بيئة معزولة، دون استخدام حسابات أو بيانات إنتاج. لم يُطبق SQL على الإنتاج، ولم يُنشر الموقع أثناء التنفيذ.

## السلوك المنفذ

- قبل إتاحة التسجيل للعامة: الأسئلة متاحة للحساب المؤهل إذا سمحت إعدادات المناظرة، واستطلاع «قبل المشاهدة» هو النموذج الحالي الوحيد. لا يغير وجود رابط التسجيل أو بدء البث الخارجي أو انتهاؤه هذه القاعدة.
- عند الإتاحة العامة: تغلق الأسئلة الجديدة ويتحول النموذج إلى تعليق، ويظهر استطلاع «بعد المشاهدة» فقط. يبقى تأكيد المشاهدة إلزامياً للمسجل مسبقاً. لا تفتح مرحلة غير مفعلة أو خارج موعدها، ولا تستخدم المرحلة الأخرى بديلاً لمرحلة غائبة.
- اختيار «سؤال» بعد الإتاحة يعرض الرسالة المطلوبة مع زر للعودة إلى التعليق، دون حقول إرسال سؤال جديد. تبقى الأسئلة السابقة ظاهرة وفق حالتها، وقابلة للإشراف.
- توجيه السؤال ظاهر دائماً: «إلى من توجه سؤالك؟»، افتراضياً «الجميع»، ثم الأسماء المنشورة الفعلية للمشاركين. يبقى اختيار المحور والنشر باسم «مشارك». هذه الحقول تخص الأسئلة فقط.
- بطاقة واحدة بعنوان «استطلاع الرأي» تجمع المرحلة الحالية، وحالة صوت المستخدم، والنتائج الحية، وإجمالي الأصوات. بعد النشر يضاف ملخص المرحلة السابقة إذا كانت متاحة، ومقارنة اختيارية بعنوان «كيف تغيرت آراء الجمهور؟» عند توفر المرحلتين.
- المقارنة تستخدم نسب الخادم نفسها. فرق النسب هو نقاط مئوية إجمالية؛ نسبة من غيّروا اختيارهم تستخدم فقط تجميع الأشخاص الذين صوتوا في المرحلتين. لا تكشف أسماء أو أصواتاً فردية، ولا تعيد حساب النسب المحجوبة من أعدادها.
- إخفاء Management يزيل النتائج الحالية والسابقة والمقارنة. تعطيل المرحلة السابقة يمنع ظهور تجميعها في البطاقة. لم تتغير سياسة الأرقام الدقيقة للنتائج الحية أو تقريب وحجب عينات اللقطات النهائية الحالية.
- رابط التنقل الوحيد «استطلاع الرأي والنتائج» يستخدم `#polls`. تفتح `#results` و`#vote-before` و`#vote-after` البطاقة نفسها. يفتح رابط المرحلة السابقة المقارنة عند توفرها، دون تكرار النماذج.
- الصفحة المفتوحة تعيد التحقق عبر قناة النتائج الحالية ونفس آلية الاستدراك الدوري. عند رفض سؤال قديم بسبب نشر التسجيل تُعرض المسودة كاملة مع النسخ أو نقلها إلى تعليق. لا يُستبدل تعليق مكتوب بصمت. تُحدّث حالة الفيديو أيضاً دون إعادة تحميل كاملة.
- سحب التسجيل يوقف التصويت بعد المشاهدة ويحافظ على إغلاق الأسئلة والمرحلة الأولى. الأرشفة والإلغاء يمنعان المشاركة الجديدة. الأسئلة والأصوات والتعليقات السابقة واللقطات محفوظة، ويمكن للمستخدم رؤية صوتيه في سجل حسابه.

## قاعدة البيانات وAPI

الملف الجديد هو [202610220002_debate_recording_lifecycle.sql](../../supabase/archive/legacy-migrations/202610220002_debate_recording_lifecycle.sql). لا يعدل أي migration قديمة.

يضيف `recording_first_published_at` كعلامة دائمة لدورة النشر. يسجل Trigger أول إتاحة عامة ويحافظ عليها عند السحب أو إعادة النشر. تستعيد الترقية الأدلة القديمة المتاحة من نسخ السجل الإشرافي أو إجراء ربط تسجيل منشور بالأعمال الإعلامية، وتتعرف إلى التسجيل المنشور حالياً. لا تستنتج الإتاحة من رابط أو انتهاء بث أو وجود أصوات بعدية. تاريخ الصفوف القديمة هو أول دليل متاح؛ لا يمكن استنتاج سحب قديم لم يحتفظ النظام بأي دليل عليه، ولذلك تُراجع هذه الحالة قبل ترقية قاعدة لها مثل هذا التاريخ.

تغلف دالة المشاركة الحالية مع إبقاء التحقق من البريد والحساب والشروط والقيود وحدود الإرسال والتصويت الوحيد وتعديل الصوت والإشراف. تقفل صف المناظرة ثم الاستطلاع، وفق ترتيب قفل الإدارة نفسه؛ القرار والتحقق والحفظ داخل المعاملة. لا توجد قراءة API منفصلة قد تصبح قديمة قبل الكتابة. يرفض API ودخول RPC المباشر المخالفة من المصدر النهائي نفسه، مع رمزي `questions_closed_after_recording` و`poll_phase_changed` ورسائل عربية عبر API. الدوال القديمة المغلفة غير متاحة للجمهور.

تضيف دالة `debate_participation_state` إسقاطاً عاماً آمناً لحالة المشاركة والمشاركين المنشورين والمحاور والاستطلاعات، دون أي سجل تصويت. يعيد مسار النتائج الحالة العامة حتى عند إخفاء النتائج، ويستخدم حسابات التجميع القائمة. توسع الترقية إشعار `debate_result_updates` الحالي؛ لا تنشئ نظام Realtime موازياً. تصفي القراءة العامة وSSR نتائج المرحلة اللاحقة قبل إتاحة التسجيل.

ترتيب الملفات عند تجهيز قاعدة جديدة: تحديثات المناظرات `202610200001` ثم `202610200002` ثم `202610200003`، ثم `202610210001_inline_editor.sql`، ثم `202610220001_debates_instant_discussion.sql`، وأخيراً الملف الجديد `202610220002`. إذا طُبقت السابقة، طبّق الجديد فقط في مشروع اختبار أولاً. لا يشغل التطبيق migrations تلقائياً.

تحديث النشر المباشر السابق `202610220001` ينشر أيضاً الأسئلة والتعليقات القديمة المنتظرة؛ راجع [دليله](instant-discussion.md) إذا لم يكن مطبقاً. هذا التحديث يحافظ على السياسة الحالية ولا يضيف موافقة مسبقة أو صلاحيات جديدة للحسابات أو الإدارة. تطبيق SQL على الإنتاج يحتاج موافقة منفصلة.

استخدمت اختبارات SQL محرك PostgreSQL معزولاً عبر PGlite وتطبيق ملفات migration الفعلية وRLS. استخدم المتصفح Next محلياً وخدمة Supabase تجريبية مرتبطة بهذه القاعدة، مع منع الاتصالات الخارجية. اختُبر الاستدراك عند انقطاع WebSocket، واختُبرت صفوف وإشعارات التحديث؛ لم يُنشأ اتصال بمشروع Supabase مستضاف أو خدمة بريد حقيقية.

لإعادة رحلة المتصفح، شغّل fixture بالخيار `--recording-lifecycle` ثم Next بمفاتيح fixture المحلية الواردة في [دليل التحرير المباشر](../inline-editor/README.md)، وأخيراً `node scripts/test-debate-recording-lifecycle.mjs`. يبدأ كل تشغيل من fixture جديدة فارغة؛ تتطلب أداة المتصفح Playwright وaxe المحليين في `.audit-tools/node_modules`.
