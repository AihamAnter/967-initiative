# ربط المشاركين في المناظرات بحسابات الأعضاء

- داخل «إدارة المناظرة › المشاركون ومواقفهم» يبقى اختيار ملف المناظر من القائمة كما كان، ويظهر بحث إضافي عن عضو بالاسم.
- عند اختيار عضو مرتبط مسبقًا بملف مناظر، يختار النظام ذلك الملف دون إنشاء حساب أو سجل آخر.
- عند تطابق الاسم مع ملف مناظر يدوي موجود وغير مرتبط، يمكن للإدارة تأكيد الربط بذلك الملف للحفاظ على سجل المشاركات السابق.
- وإلا يمكن إنشاء ملف مناظر جديد منشور بالاسم العام للعضو ورابط قصير ثابت قابل للتعديل، ثم اختياره في المناظرة. يجب حفظ المناظرة بعد الاختيار لتثبيت المشاركة.
- في «ملفات المشاركين» يوجد بحث مستقل لربط حساب عضو بملف جديد أو موجود. الاسم يملأ تلقائيًا، بينما تظل حقول الاسم والرابط القصير والتخصص والنبذة والصورة والروابط وحالة النشر متاحة للتعديل.
- لا ينشئ هذا المسار حسابات Auth، ولا يغير بيانات العضو الشخصية أو بريده أو أذوناته.
- `debate_speakers.member_user_id` مرجع اختياري فريد إلى `public_profiles.user_id` (مع `ON DELETE SET NULL`). تتحقق قاعدة البيانات من وجود حساب مؤكد ونشط وقابل للظهور عند الربط.
- الإسقاطات العامة تخفي ربط حساب موقوف أو قيد الحذف أو أوقف الظهور في البحث.
- صفحة `/debates/speakers/[slug]` تربط إلى `/members/{member_user_id}` حين يوجد ربط فعلي؛ وإلا تبقي الرابط التجريبي السابق.
- مسار `/api/admin/debates/member-search` لا يكشف البريد، ولا يتاح إلا للأدمن والإدارة بعد التحقق من JWT والصلاحيات على الخادم.

ترحيل Supabase المطبق: `20261103162149_link_debate_speakers_to_existing_members.sql`. لا يغير أيًا من ملفات المناظرين الحالية حتى تختار الإدارة حسابًا وتربطه يدويًا.

اختبارات: `node --test tests/debate-member-picker.test.mjs`، واختبار إضافة عضو جديد، ربط ملف قديم، منع الربط المكرر، ظهور ملف عضو حقيقي، والمستخدم المخفي.
