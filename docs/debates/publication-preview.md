## تصحيح خطأ تشغيل SQL — استخدم 220004

أُعيد إنتاج رسالة `Review the current audience mutation before repairing publication` عند نسخ ملف `202610220003` بفواصل أسطر Windows ‏CRLF. كان تعريف الدالة يُوحّد إلى LF، بينما يبقى جزء المقارنة متعدد الأسطر بتنسيق الملف المنسوخ. فشل الفحص قبل تغيير سياسة القاعدة. هذا يثبت سبباً قابلاً لإعادة الإنتاج للرسالة؛ لا يستنتج وحده تنسيق تعريف الدالة الفعلي على الإنتاج.

استخدم الملف المستقل [202610220004_debate_discussion_publication_portable.sql](../../supabase/migrations/202610220004_debate_discussion_publication_portable.sql) **كاملاً بدلاً من إعادة محاولة 220003**. يمكن تشغيله مباشرة بعد دورة التسجيل `220002` إذا فشل الملف السابق، أو بعد `220003` إذا نجح سابقاً. لا يحتاج إلى إعادة تشغيل الملفات القديمة، ويقبل إعادة تشغيله بأمان. إذا بقيت جلسة SQL نفسها في حالة `25P02` بعد المحاولة الفاشلة، نفّذ `ROLLBACK;` لإنهاء المعاملة الفاشلة ثم شغّل الملف الجديد كاملاً.

يعالج 220004 الأجزاء الثلاثة المطلوبة فقط: حالة إنشاء التعليق، وحالة إنشاء السؤال، والمحافظة على قرار الإشراف عند تعديل التعليق. يتقبل اختلاف المسافات والأسطر وCRLF وكِبَر حروف كلمات SQL والمعرّفات غير المقتبسة. يحافظ على النصوص والمفاتيح المقتبسة بحساسيتها لحالة الأحرف. لا يطابق أو يعيد كتابة `RETURN`؛ يستمر API في قراءة حالة السجل الفعلية عبر مسار التوافق عند الحاجة. تبقى فحوص دورة التسجيل والصلاحيات والردود والتصويت والإشراف كما هي. لا تُنشر المشاركات القديمة تلقائياً.

يبقى الفحص صارماً مع أي تعبير غير معروف، ويحدد اسم الجزء المختلف في رسالة الخطأ بدلاً من استبدال تعريف مخصص بصمت. اختُبرت نسخة CRLF بعد فشل 220003، والتعريف المعاد تنسيقه، والكلمات الكبيرة، والتطبيق بعد إصلاح سابق، والتشغيل المتكرر، ورفض تغيير مفاتيح JSON أو تعبير إدخال غير معروف. نجح `npm test` بإجمالي **236 اختباراً**، ونجحت رحلات المتصفح الـ16 مع 220004 نفسه دون أخطاء تشغيل أو Hydration أو مخالفات axe مكتشفة على المقاسات الأربعة. لم يُعدل ملف migration القديم ولم يُطبق أي SQL على الإنتاج أثناء هذا التصحيح. [اختبارات التصحيح](evidence/publication-portable-tests.txt)، [رحلات المتصفح مع 220004](evidence/publication-portable-browser.json).

وُجد أيضاً خلل مستقل في رسالة الواجهة: كانت تفترض «نُشر» بعد استجابة تحوي المعرّف فقط، حتى لو كانت القاعدة قد حفظت السجل بانتظار المراجعة. أُصلح ذلك من API إلى الواجهة.

## الإصلاح الخلفي والنشر

الملف الجديد [202610220003_debate_discussion_publication_repair.sql](../../supabase/migrations/202610220003_debate_discussion_publication_repair.sql):

- يضبط القيم الافتراضية إلى `approved`، ويجعل دالة إنشاء التعليق والرد والسؤال تحفظ `approved` صراحةً. لا تعود الكتابة من RPC معتمدة على القيمة الافتراضية وحدها.
- يصلح الدالة الأصلية الموجودة داخل غلاف دورة التسجيل، بدلاً من استبدال الغلاف أو تجاوز قفله. يستمر إغلاق الأسئلة بعد نشر التسجيل والتحقق من مرحلة التصويت.
- يحافظ تعديل التعليق على قرار الإشراف: المنشور يبقى منشوراً، والمخفي أو المرفوض لا يعيد صاحبه نشره بتعديل النص.
- يعيد حالة السجل الفعلية مع معرّفه. يستخدم API الحالة مباشرة، ويقرأ حالة السجل بصلاحيات صاحبه للتوافق مع مخطط أقدم يعيد المعرّف فقط. إذا تعذر فحص الحالة بعد حفظ مؤكد، لا يحول الحفظ إلى خطأ يدفع المستخدم لإرسال نسخة مكررة.
- يرفض إصلاح تعريف دالة غير متوقع ويترك المعاملة دون تطبيق جزئي. يحتفظ بحدود الإرسال وتأكيد البريد والملكية والردود والمحاور والخصوصية وRLS وأدوات الإشراف.
- **لا يغيّر حالة أي مشاركة قديمة**، ولا يعيد نشر المحتوى المخفي أو المرفوض أو المحذوف، ولا يحذف بيانات أو يعدل سجل الإشراف.

رسالة الواجهة تصف النتيجة المؤكدة: منشور، أو محفوظ بانتظار المراجعة، أو تعديل محفوظ مع بقاء قرار الإشراف، أو حفظ تعذر التحقق من ظهوره. لا تُعرض رسالة نجاح قبل استجابة الخادم. يعاد جلب الساحة والعدد بعد الحفظ؛ لا يتكرر السجل عند الجلب اللاحق. يبقى النص عند فشل الحفظ.

### ترتيب التطبيق الآمن

1. خذ نسخة احتياطية واستخدم مشروع اختبار مستقل أولاً. يلزم مخطط المناظرات الأساسي `202610200001` ثم `202610200002` ثم `202610200003`، والتحرير المباشر `202610210001`، ودورة التسجيل `202610220002`.
2. في تثبيت مرتب تكون سياسة النشر `202610220001` مطبقة قبل دورة التسجيل، ثم يطبق الإصلاح الجديد. اختُبر هذا التسلسل.
3. في الحالة التي يحاكيها التشخيص الحالي، حيث توجد `202610220002` وتبقى القيم `pending/new`، **استخدم الإصلاح الجديد `202610220003` بعد التحقق من المتطلبات. لا تُعد تشغيل `202610220001` القديمة بعد غلاف دورة التسجيل**؛ فهي تتوقع الدالة قبل تغليفها، وتنشر المشاركات القديمة المنتظرة تلقائياً.
4. راجع الملف الجديد ثم طبقه في قاعدة الاختبار. تحقق من القيم الافتراضية ومن إنشاء تعليق ورد وسؤال، وإخفائها واستعادتها، وعدم فتح الأسئلة بعد التسجيل. عند اختلاف تعريف الدالة يتوقف الملف ويحتاج مراجعة التعريف؛ لا تتجاوز الفحص بتعديل migrations القديمة.
5. تطبيقه على الإنتاج يحتاج موافقة صريحة منفصلة، ثم تحقق فعلي بعد التطبيق. لم تُمنح هذه الموافقة في هذه المهمة ولم يُطبق الملف هناك. يلزم أيضاً نشر تغييرات التطبيق لرسائل الحفظ والغلاف وبطاقة الموعد.

تبقى المشاركات القديمة المعلقة خاصة حتى تُراجع. لمعالجتها استخدم طابور الإدارة أو التحرير المباشر، وحدد المشاركات المراد اعتمادها فقط مع سبب موثق. يظهر المحتوى المحدد للجمهور بعد الاعتماد؛ تبقى الهوية المجهولة محجوبة. لم أنفذ اعتماداً جماعياً أو SQL يحرر المحتوى القديم دون موافقة.

## الغلاف والموعد

تستخدم منطقة التسجيل نفسها `cover_url` قبل الإتاحة العامة، بنسبة 16:9 مع `object-fit:cover` ودون زر تشغيل وهمي. الغلاف المفقود أو الذي يفشل تحميله يعرض احتياطاً من هوية 967 بدلاً من صورة مكسورة؛ لا يصبح الغلاف إلزامياً للمناظرات القديمة. أُعيد استخدام هذا المكون في بطاقات المناظرات أيضاً.

للمسجلة مسبقاً تظهر بطاقة غير مطوية بعنوان «موعد نشر المناظرة» بجانب الغلاف على الشاشات الواسعة وتحته على الهاتف، مع تاريخ كبير وساعة واضحة و«بتوقيت اليمن». يمنع العرض الجانبي الغلاف الكبير من دفع الموعد خارج الشاشة الأولى على الكمبيوتر. مصدرها `scheduled_at` الحالي، ويستخدم التنسيق `Asia/Aden` باستقلال عن توقيت الزائر أو المحرر. عند غياب الموعد تظهر «موعد النشر سيُعلن لاحقاً». توضح حقول الإدارة والتحرير المباشر أن الإدخال بتوقيت جهاز المحرر وأن العرض العام بتوقيت اليمن، دون تغيير التخزين أو التحويل الحاليين.

التأجيل والإلغاء لا يعرضان الموعد القديم كوعد قائم. بعد نشر التسجيل تختفي بطاقة الموعد ويتحول الموضع إلى المشغل الحالي مع الغلاف كمعاينة، والفصول والرابط الخارجي. يظل تحميل YouTube مؤجلاً إلى تشغيل المستخدم أو اختيار فصل. تغيير مصدر الفيديو يعيد حالة المشغل قبل أي تشغيل. عند سحب التسجيل يعود الغلاف مع رسالة عدم الإتاحة، دون إعادة فتح الأسئلة أو المرحلة الأولى أو إظهار الموعد القديم.

البث الخارجي الجاري والمنتهي يحتفظان برابط المنصة. لا يعتبر الرابط أو انتهاء البث نشراً للتسجيل. يظهر تنبيه المشاركة قبل التسجيل وفق إعدادات الأسئلة والاستطلاع. تستمر الأقسام الحالية وروابطها وترتيب المشاركين والاستطلاع الموحد وساحة النقاش. تعيد آلية تحديث الحالة الحالية التحقق من رأس الصفحة والغلاف والموعد عند حفظ تغييرات المناظرة، دون نظام Realtime جديد.
