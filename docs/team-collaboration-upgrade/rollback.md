# خطة التراجع

تُستكمل بعد اختبار الترحيلات. السياسة الأساسية: التراجع البرمجي لا يحذف بيانات المشاركين أو الردود أو السجل الجديد، ولا يعيد تهيئة الجداول.

- الحفاظ على `assigned_to` ومسار قراءة المهام القديمة يسمحان بتعطيل الواجهة الجديدة دون فقد المسؤول الرئيسي.
- إيقاف الكتابة مؤقتًا أثناء التراجع عن أي بنية، مع حفظ نسخة بيانات جديدة أولًا.
- السجل التحريري وتاريخ تفعيله محفوظان؛ لا حذف للأحداث لتحسين الأرقام أو إخفاء عمليات سابقة.
- أي تعطيل Trigger أو RPC يحتاج مراجعة الصلاحيات والتوافق وخطة إعادة تفعيل؛ لا أوامر تراجع إنتاجية تُنفذ تلقائيًا.
