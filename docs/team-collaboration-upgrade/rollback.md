# خطة التراجع وحفظ البيانات

الوضع الحالي: الترحيلات محلية فقط، ولم يتغير الإنتاج أو main. يمكن رفض الفرع دون أي تراجع إنتاجي؛ تبقى الأدلة والكود للمراجعة.

## فشل أثناء التطبيق

كل ملف migration معاملة؛ فشلها يلغي تغييرات ذلك الملف. إذا نجح 004 وفشل 005 أو 006، سجّل الملفات المنفذة وأبقِ النشر متوقفًا حتى معالجة السبب. لا تعِد تشغيل Seed أو تهيئة جداول، ولا تحذف الأعمدة الجديدة لتجربة الحظ.

أخذ Backup واختبار استعادته قبل نافذة التطبيق شرط تشغيلي في [قائمة التطبيق](deployment-checklist.md). يضمن اختبار Staging أن الخادم والواجهة والـSQL ينشرون بإصدارات متوافقة.

## بعد بدء استقبال بيانات جديدة

التراجع المفضل إصلاح أمامي أو تعطيل مدخل الواجهة المتأثر مؤقتًا مع إبقاء البيانات وواجهات الحفظ الآمنة. يحتفظ assigned_to بمعناه القديم، لكن الرجوع الأعمى إلى عميل قديم ليس كامل التوافق: تعديل التعليقات يتطلب comment_revision، واستدعاءات الخدمة الجديدة تحتاج RPC الموافق. لا تعطل حارس النسخة لإرضاء تبويب قديم.

لا تُسقط task_members أو parent_id أو التعليقات المحذوفة نصيًا أو جدول المساهمات. لا تنقل الردود بتغيير آبائها، ولا تمسح الأحداث الجديدة أو المسؤوليات. يمكن قراءة الحقول الأصلية مع الحقول الجديدة حتى يُجهز إصدار متوافق من الواجهة.

المراجع الأصلية للدوال محفوظة أثناء الترقية باسم task_mutate_legacy وeditorial_debate_mutate_legacy، لكنها ليست خطة تراجع منفردة: الحراس والسياسات والتواقيع التابعة تغيرت. إعادة اسم دالة واحدة أو نشر ملف SQL قديم وحده قد يكسر التوافق؛ لا يقدم هذا الفرع سكربت DROP غير مختبر على بيانات إنتاجية.

## إذا لزم رجوع كامل

1. أوقف الكتابة وفق نافذة تشغيل معتمدة، وخذ نسخة كاملة من الحالة الجديدة وسجل المساهمات والملفات الخاصة.
2. استعد Backup السابق إلى قاعدة منفصلة، وليس فوق قاعدة تستقبل العمل.
3. صدّر جميع تغييرات ما بعد التفعيل، بما فيها المشاركون والردود ونسخ الملفات والأحداث، وجهز خطة تسوية يراجعها مسؤول البيانات. لا تفترض إمكان حذفها لأنها أحدث.
4. اختبر المسؤوليات والتعليقات والأنشطة والأصوات والإحصاءات وتسجيل الدخول على النسخة المستعادة والمتوافقة.
5. بعد اعتماد المستخدم ومسؤول التشغيل فقط، قرر التحويل أو الإصلاح الأمامي. لم تنفذ هذه المهمة تحويلًا أو استعادة أو إجراءً إنتاجيًا.

المسار الآمن لا يعد بعكس DDL تدميري بلا فقد بيانات؛ يحافظ على النسخة الجديدة وعلى قابلية المراجعة حتى تُعتمد التسوية.
