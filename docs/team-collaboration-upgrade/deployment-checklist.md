# قائمة التطبيق بعد المراجعة

لم ينفذ أي بند إنتاجي أدناه. طلب المستخدم مراجعة التغييرات والموافقة عليها قبل الدمج أو النشر.

## قبل نافذة التطبيق

- مراجعة [الترحيلات](database-migrations.md) و[تغطية السجل](editorial-audit-coverage.md) والصلاحيات مع مسؤول قاعدة البيانات.
- مطابقة تاريخ migrations في البيئة مع الشروط السابقة، والتأكد من وجود كل الجداول والدوال والأدوار المطلوبة. لا تشغل ملفات التهيئة أو Seed فوق بيانات قائمة.
- إنشاء Backup قابل للاستعادة لقاعدة البيانات وStorage، وتسجيل عدد المهام والتعليقات والأنشطة والمسؤولين والأصوات والقيم الإحصائية قبل التطبيق.
- تجربة نفس الترتيب على Staging ببيانات مجهولة الهوية أو مصطنعة، وفحص زمن DDL والفهارس والعلاقات على حجم قريب من الحقيقي.
- التأكد من صلاحية service_role على RPC الجديد فقط، وبقائه على الخادم؛ Dashboard تستخدم JWT المستخدم وRLS.

## الترتيب

1. نافذة متفق عليها لتطبيق 004 ثم 005 ثم 006 عبر آلية migrations المعتمدة؛ كل ملف معاملة مستقلة.
2. إذا فشل ملف، لا تنشر واجهة تعتمد عليه. افحص سبب الفشل وحالة سجل التطبيق، ولا تحاول تجاوز الجدول أو السياسة المفقودة.
3. نشر إصدار الخادم والواجهة المتوافقين مع نسخ التعليقات وRPC الخدمة الجديد في النافذة نفسها. اطلب تحديث التبويبات القديمة؛ لا تفتح bypass للنسخة.
4. التحقق بحسابَي Admin وManagement ومستخدم عادي: مهمة قديمة، أعضاء وردود، اعتماد وتكرار وأرشيف، حفظ محتوى، حدث واحد صحيح، ورفض قراءة اللوحة لغير المخول.
5. اختبار Storage الفعلي للسير الموسعة ومزود المصادقة على Staging، ثم فحص مسارات التنقل والمقاسين 1440 و390.
6. مطابقة الأعداد والمسؤوليات والقيم والأصوات السابقة؛ السجل الجديد يبدأ من وقت تفعيله دون backfill.
7. بعد القبول فقط، اعتماد الدمج/النشر الإنتاجي ومراقبة أخطاء API وCAS؛ لا تنفذ تحديث Provider أو استيراد محتوى كجزء ضمني من نشر هذه الميزة.

## إعادة الفحص محليًا

القاعدة الاصطناعية: `TEAM_UPGRADE_APPLY=1 node scripts/team-upgrade-fixture.mjs` على 3449. شغل Next على 3149 مع NEXT_TEAM_PREVIEW=1 ومفاتيح fixture-anon/fixture-service الوهمية وURL القاعدة المحلية؛ لا تستخدم مفاتيح الإنتاج.

تُنفذ دالتا [اختبار المتصفح](../../scripts/team-upgrade-browser.mjs) و[التغطية الموسعة](../../scripts/team-upgrade-coverage-browser.mjs) بواسطة Playwright MCP، بالترتيب، بعد تشغيل fixture جديد. الدالتان ترفضان بيئة لا تحمل production=false. لا تشغلهما ضد موقع منشور.

`node --test --test-concurrency=2 tests/*.test.mjs` ثم `npm run lint` و`npm run build`. إعداد NEXT_VALIDATION_BUILD يعزل مخرجات البناء عن خادم المراجعة الجاري. لا تغيّر .env.local أو ترفع مفاتيح أو جلسات ضمن الأدلة.
