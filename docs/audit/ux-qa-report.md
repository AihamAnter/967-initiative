تاريخ المراجعة: 16 أكتوبر 2026. الفرع: `audit/launch-readiness`.

## النطاق وحدود الأدلة

راجع متخصص UI/UX المكونات العامة للتنقل، البحث والفلاتر، الأدلة، المشغّل، المجلة وقارئ PDF، الخريطة، المؤشرات والمقارنة الزمنية، نموذج التواصل، المشاركة، RTL وإمكانية الوصول. نفّذ الإصلاحات داخل المشروع القائم مع الحفاظ على الألوان والهوية والمحتوى. لم ينشر تغييرات، ولم يغيّر بيانات الإنتاج.

أجرى المدير التقني فحص المتصفح الأساسي المشترك وحفظه في [`evidence/browser-before.json`](evidence/browser-before.json): **19 صفحة، 152 فحص عرض عبر 8 مقاسات، 38 فحص axe**. راجع متخصص UX تفاصيل هذه النتائج. نجاح عرض الوثيقة بعرض النافذة لم يكن وحده كافياً: سجل الفحص عناصر من قائمة الهاتف خارج العرض عند 320px، رغم عدم ازدياد `scrollWidth`، ولذلك أضيف إصلاح للقائمة.

أعاد المدير التقني اختبار النسخة المدمجة: [`evidence/browser-after.json`](evidence/browser-after.json) يسجل **19 صفحة، 152 فحص عرض ناجحاً، 38 فحص axe دون مخالفات، 13 سيناريو تفاعل ناجحاً، وصفر أخطاء runtime**. الصور الحديثة للمجلة والخريطة عند 390px روجعت بصرياً وتعرض CSS وRTL الصحيحين. جولة سابقة التقطت أصول CSS قديمة بسبب خادم لم يُعد تشغيله؛ أعيد تشغيله وأعيدت اللقطات، ولم تعتمد اللقطات القديمة دليلاً للنتيجة الحالية. كما صُححت محددات الاختبار العربية قبل اعتماد النتائج.

**كشف فحص ملف PNG المنزّل بصرياً، بعد نجاح اختبار التنزيل الآلي، مشكلة إضافية UX-21.** نُفّذ إصلاحها، واختُبر المساعد الجديد فعلياً داخل DOM الرسم الحالي، وفُحص الملف الناتج بصرياً. أعاد المدير بناء النسخة المدمجة وتحقق من التنزيل الفعلي وفحص PNG بصرياً. نجاح 13 سيناريو سابقاً لا يُستخدم وحده لإثبات صحة صورة PNG؛ دليلها المباشر موضح أدناه.

لا توجد بيئة staging أو حساب اختبار، بحسب تأكيد المستخدم. لم يُختبر دخول ناجح أو حفظ محتوى حقيقي أو إرسال رسالة فعلية إلى قاعدة الإنتاج. اختبار واجهة التواصل باستجابة وهمية يثبت سلوك الواجهة فقط.

## الاختبارات المنفّذة فعلياً

`node --test tests/ux-navigation.test.mjs`: **6 اختبارات ناجحة، 0 فشل**. تغطي تنقل PDF لكل أعداد الصفحات 1–40، الأرقام والكسور، 4000 عملية zoom، إحداثيات SVG، حساب المقارنة والفجوات والصفر، وسلامة روابط الوسائط والصور المحلية. انحدار تصدير الصورة يختبر في DOM المتصفح الحقيقي كما يلي.

## نتائج إعادة الفحص المدمج

اطّلع المتخصص على JSON النهائي المتاح قبل إصلاح UX-21. اجتازت القائمة المتنقلة وإرجاع التركيز، قائمة الحاسوب والرجوع، البحث العربي وحالات الفراغ، القارئ وأرقام الصفحات والنص المستخرج والتنزيل، فشل PDF والخريطة وإعادة المحاولة، تبديل مديريات الخريطة، رفض الحافظة ونسخ الرابط اليدوي، جدول المقارنة وCSV، نجاح التواصل الوهمي وفشل JSON/الشبكة مع حفظ النص. لم تُرسل رسالة حقيقية.

نجحت **152/152** حالة عرض، بما فيها فلاتر المنتجات 320px بعد UX-20. زالت مخالفات أسماء البطاقات والخريطة وبنية بيانات الشخصية في **38/38** فحص axe. ما زالت بعض حالات `color-contrast` في الرسوم/الوسائط تتطلب حكماً يدوياً؛ لم تحوّل حالات `incomplete` إلى نجاح مزعوم. اختبار تصدير PNG السابق أثبت تنزيل الملف فقط؛ كشف الفحص البصري UX-21 وعولج منفصلاً كما سبق.

## سيناريوهات إعادة الفحص المطلوبة

1. هاتف 320/360/390px: ظهور زر القائمة كاملاً، فتح كل أقسامها، Tab/Escape، وعدم اقتطاع نص عربي طويل.
2. الحاسوب: فتح dropdown وإغلاقه بـEscape وإرجاع التركيز لـsummary الصحيح، الدخول لمسار داخلي والرجوع.
3. البحث العام والأدلة والأعمال والأعداد والمؤشرات: بحث عربي، فلتر واحد ومركّب، نتائج صفرية، مسح، صفحة تالية، فتح التفاصيل مباشرة.
4. PDF: ملف demo والعدد المنشور، كتابة رقم متعدد الخانات، كسور/حدود، آخر صفحة زوجية، صفحتان/صفحة وتغيير العرض، التكبير، البحث بنتيجة/دون نتيجة، استخراج النص، تحميل الملف، ملف معطل وإعادة المحاولة.
5. الخريطة: تحميل فعلي، لوحة مفاتيح/لمس/عجلة، اختيار محافظة ومديرية، إخفاء/إظهار المديريات بعد الاختيار، إغلاق اللوحة وإعادة الضبط، بحث بالأسهم وEscape، فشل البيانات وإعادة المحاولة.
6. المقارنة: وحدة متوافقة/مختلفة وحد أربعة مؤشرات، تغير الفترة، أساس صفر/مفقود، جدول بديل، CSV وPNG صالحان.
7. المشاركة: نجاح الحافظة ورفضها، إلغاء المشاركة الأصلية، اختيار الرابط اليدوي.
8. نموذج التواصل: browser validation، نجاح mocked فقط، 503 JSON وغير JSON، انقطاع اتصال، بقاء الرسالة، عدم تكرار الإرسال.
9. axe مجدداً على 390px و1440px، خاصة المؤشرات والمنتجات والخريطة وقائمة بيانات الشخصية.

## القيود والتوصيات المتبقية

- لا يحل استخراج PDF محل مراجعة ملفات المجلة نفسها: الملفات المصورة تحتاج OCR ونصوصاً بديلة ومراجعة ترتيب القراءة من الناشر. لم يُختبر NVDA أو VoiceOver على جهاز فعلي.
- دعم الفيديو يظل معتمداً على نشر المزود وصلاحية التضمين والاتصال؛ لا يمكن فحص محتوى iframe بين النطاقات برمجياً كدليل تشغيل كامل.
- اختبار captcha الحقيقية واستلام الرسالة فعلياً وحسابات الدخول والتحرير يحتاج بيئة اختبار وحساباً مخصصاً؛ لم ننشئ سجلات اختبار في الإنتاج.
- اختبار widths في Chromium ليس اختبار هاتف فعلي ولا Safari/Firefox. لا يُمنح مجال الهاتف أو إمكانية الوصول درجة كاملة بناءً عليه.
- مراجعة تباين عناصر SVG/الفيديو الآلية قد تظهر حالات `incomplete`؛ لا تُوصف تلك الحالات بأنها اجتازت فحصاً يدوياً دون دليل إضافي.
- لا يُعلن متخصص UX الجاهزية النهائية مستقلاً. تحددها نتائج النسخة المدمجة والاختبارات الأساسية وقيود الإدارة/التواصل في التقرير الموحد.

## التقييم الداخلي

يُحسب تقييم UX من سلوك التنقل 3 نقاط، قابلية اكتشاف المحتوى والفلاتر 3، أخطاء/تحميل/فراغ 3، وصول لوحة المفاتيح والنصوص البديلة 3، وتناسق/قابلية قراءة الواجهة 3؛ الإجمالي 15. التقدير الداخلي **9.5/15 قبل العمل → 13.5/15 بعد الإصلاح والتحقق المتاح**: قبل العمل (2،2،1.5،1.5،2.5)، وبعده (3،3،2.5،2.5،2.5). نقص النقاط الباقية يعكس عدم اختبار قارئ شاشة فعلي، وعدم ضمان ترتيب نص ملفات PDF أو جميع مزودي الوسائط، وحالات SVG/تصدير طويلة تحتاج مراجعة إضافية. هذا تقدير مهني داخلي يستند إلى المصادر والأدلة، وليس درجة أداة معتمدة. تقييم الهاتف10 والإجمالي100 وحالة الجاهزية يقررها المدير من الأدلة المدمجة والقيود المتبقية.
