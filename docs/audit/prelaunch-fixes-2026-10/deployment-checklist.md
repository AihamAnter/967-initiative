# خطوات الإطلاق الخارجية المطلوبة

الكود **READY FOR REVIEW**. لا تنشره قبل إكمال الخطوات الجوهرية أدناه. لم يُنشر الموقع ولم تُطبق SQL على الإنتاج بهذه المهمة.

1. في مشروع Supabase Staging مستقل بمخطط مطابق، راجع السياسات والدوال الحالية واعتماد مخططات الأقسام الموجودة. اختبر migrations بالترتيب:202610230001_prelaunch_roles_rls.sql ثم 202610230002_management_guard.sql ثم 202610230003_contact_workflow.sql. لا تعِد تطبيق ملفات قديمة أو launch-hardening-proposed.sql تلقائياً.
2. اختبر عبر واجهة Supabase الحقيقية anon/عضو/بريد غير مؤكد/Admin/Management/Auth-banned/دور مسحوب؛ القراءة العامة والمسودات والأبناء والمصدر المعطل، تغيير الأدوار المتزامن، Storage/رفع/جلسة منتهية وخروج. يحتاج المحرر المعتمد بريداً مؤكداً وغير محظور.
3. تحقّق من L-01:الـ metadata الإنتاجية الحالية approved لكليهما، لكن ذلك لا يكفي لإثبات جسم الدالة. راجع function definitions ورحلة نشر/إخفاء/تعديل في Staging. لا تنشر بيانات اختبارية على الإنتاج ولا تعِد الإصلاح 202610220004 دون إثبات الحاجة.
4. اختبر حفظ التواصل→new→in_progress→resolved عبر API و RLS. يجب اعتماد RPC contact_rate_limit وحقول status قبل نشر الكود؛ غيابها يعيد 503 عمداً ويحفظ مسودة المستخدم.
5. اختبر Supabase Confirm Email و SMTP و Site URL و Redirect URLs وروابط التأكيد/الاستعادة وانتهائها واستعمالها مرة واحدة. الاختبارات المحلية لا ترسل بريداً.
6. إذا كان Turnstile مفعلاً، احتفظ بالمتغيرين الموجودين للـ site key والـ secret مع hostname مطابق و action=contact، واختبر challenge حقيقياً وحد الإرسال على نسخ Vercel متعددة. CONTACT_RATE_LIMIT_SECRET اختياري؛ عند غيابه يستخدم المفتاح الخدمي الموجود. لا سر NEXT_PUBLIC جديد ولا خدمة مدفوعة مطلوبة.
7. اضبط حالة مشروع المناظرات الفعلية من الإعدادات بقرار المالك؛ البيانات التجريبية لا تعلن الإطلاق. تحقق من صلاحية تضمين روابط الفيديو النهائية خارجياً.
8. بعد اعتماد SQL ونجاح Staging، اطلب تفويض نشر الإنتاج وتطبيق خطة الترحيل على المخطط الصحيح، ثم أعد smoke و 404 و Sitemap/robots/canonical/social/noindex. راجع أحداث source_unavailable وفشل التواصل في سجلات المضيف.
9. أعد Lighthouse و LCP/TTFB على الاستضافة في مرور ممثل، واجمع INP ميدانياً عند توافر بيانات كافية؛ لم تثبت هذه المهمة اجتياز Core Web Vitals. افحص أجهزة فعلية و Firefox/Safari وقارئ شاشة عند توافرها.
10. عبر حساب المالك في Search Console/Bing Webmaster، تحقق من ملكية النطاق، أرسل sitemap.xml وافحص صفحات عامة وخاصة. لم تكن الأدوات متصلة ولا يوجد ادعاء فهرسة.

الرجوع:احتفظ بنسخة من تعريفات السياسات/الدوال ونسخة قاعدة وفق إجراءات المشروع قبل التطبيق. migrations إضافية ولا تحذف المحتوى؛ لا تحذف أعمدة الرسائل أوتعيد الحارس المقترح القديم ارتجالاً. إن تعذر اعتماد المخطط، أبق الكود السابق المنشور حتى اكتمال Staging. لا خطة نقل ملفات سرية إلزامية ما لم يصنّف المالك ملفات بعينها كذلك؛ خطة مشروطة مفصلة في security-notes.md.
