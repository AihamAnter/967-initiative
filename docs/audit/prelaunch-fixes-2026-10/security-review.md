# مراجعة الأمان والخصوصية

التنفيذ والأدلة المفصلة في [security-notes.md](security-notes.md)، ومراجعة مستقلة في [supervisor-review.md](supervisor-review.md).

- حراس الخادم و RLS يفحصون الدور الحالي والبريد المؤكد وحظر Auth؛ سحب الدور يرفض API والبيانات الخاصة. تعليق المشاركة منفصل عن حظر حساب Auth وتظل قواعده الأصلية.
- سياسات المحتوى العام تفرض نشر الوالد ونشاط المصدر؛ لا تغيير لبيانات المصادر أو المحتوى.
- عدّاد آخر Management ذري ومثبت باتصالين PostgreSQL فعليين؛ تطبيقه المستضاف إجراء منفصل.
- الرسائل الخاصة:قراءة للمحرر المؤهل وتحديث عمود status فقط؛ محتوى الرسالة والمرسل لا يغيرهما المستخدم عبر صلاحية المتابعة. المراجع allowlist محلي وليست صلاحية أو حقيقة موثوقة.
- منع الإغراق مشترك PostgreSQL، 8/10 دقائق، HMAC لا IP خام. التنظيف عند الطلب التالي وليس Cron؛ البصمات مستعارة وليست ضمان إخفاء هوية. Vercel فقط يوفّر header الهوية الموثوق المستخدم؛ المضيف الآخر يحتاج adapter مناسباً.
- مسودة المناظرة sessionStorage للتبويب 30 دقيقة، مرتبطة بالمالك؛ handoff عشوائي لمرة واحدة وبعد session فقط. لا نص في URL أو localStorage أوإرسال تلقائي. التخزين الممنوع لا يعطل الدخول.
- التسجيل التشغيلي schema مغلق؛ يحذف query/هوية/نصوص/أخطاء خام و tokens. سجلات client محدودة ولا تكشف payload. لا خدمة تنبيه خارجي أو dashboard متصل مثبت.
- media عام؛ تنبيه الرفع يشرح المسودات غير السرية. لا ملف سري محدد مثبت، ولم نغير bucket أو نكسر الروابط. خطة الترحيل المشروطة في ملاحظات الأمن.

migrations الثلاث الجديدة اختُبرت محلياً ولم تُطبق على الإنتاج. ملف launch-hardening-proposed.sql تاريخي؛ لا تطبقه فوق الخطة الجديدة دون مراجعة لأنه قد يستبدل الحارس. لا تغییر لمفاتيح البيئة الحقيقية أو حسابات الإنتاج أو الأصوات أو دقة النتائج.

راجع [قائمة النشر](deployment-checklist.md) لاختبارات JWT/REST/Storage و SMTP/CAPTCHA المستضافة.
