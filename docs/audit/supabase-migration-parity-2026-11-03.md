## متابعة مستقبلية

بعد `git pull --ff-only`، ومع ربط Supabase CLI بالمشروع يمكن مراجعة السجل باستخدام:

```powershell
npx supabase migration list
```

لا تنفذ `supabase db push` قبل مراجعة السجل عند وجود اختلافات جديدة، ولا تستخدم `migration repair --status applied` إلا بعد إثبات أن التغيير **موجود فعليًا** في قاعدة البيانات. لا تضف ملف ترحيل جديدًا برقم غير مكوّن من 14 رقمًا. بعد أي ترحيل مستقبلي، احتفظ بملف SQL المنفّذ في GitHub **بنفس رقم الإصدار المسجل في Supabase**.
