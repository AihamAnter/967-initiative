# مركز إشعارات 967 الموحد — 4 نوفمبر 2026

## نطاق التنفيذ

المرحلتان الأولى والثانية: واجهة موحدة داخل `/notifications` وجرس في رأس الموقع للمستخدم المسجل. تشمل إشعارات الحساب والمناظرات، ومركز المهام للمحررين، والرسائل الخاصة مجمعة حسب المحادثة.

- `/api/notifications?mode=summary` يعيد عداد الإشعارات الجديدة وأحدث خمس تحديثات للجرس، ويُحدث كل 60 ثانية فقط أثناء ظهور الصفحة أو عند العودة للمتصفح أو بعد الإجراء.
- `/api/notifications?mode=list&category=all&page=1` يعيد 20 إشعارًا في الصفحة، مع التصفية إلى `messages` و`tasks` و`debates` و`account`. يمكن تحميل صفحات أقدم حتى عشر صفحات دون نسخ الإشعارات أو تخزينها في جدول جديد.
- تستخدم صفحة `/notifications` فلاتر، وعناوين، ومواعيد، ومؤشرات غير المقروء، وفتح المصدر، وتحديد كل إشعارات الحساب والمهام كمقروءة. قراءة إشعار الرسالة لا تعني قراءة المحادثة؛ تُعتمد قراءة الرسالة فقط عند فتحها.
- تحافظ صفحة حسابي على قسم الإشعارات القديم وتضيف رابطًا للمركز الجديد، للحفاظ على روابط المستخدمين القديمة.
- لا تُظهر الجرس للقارئ غير المسجل، ولا تستخدم أصواتًا أو Realtime إضافيًا.

## مصادر البيانات ومنع التكرار

- `account_notifications`: إشعارات حسابك والمناظرات (المقيدة بـ`user_id` وRLS).
- `task_notifications`: إشعارات مهام الفريق (حساب المحرر المعتمد فقط عبر RLS و`task_role()`). يُجلب اسم المهمة من جدول `tasks` المرئي للمستخدم. روابط التعليقات تشير إلى نفس المهمة والتعليق.
- `private_messaging_inbox`: عبر استدعاء الخدمة بعد التحقق من جلسة المستخدم ووضع حسابه؛ كل محادثة فيها رسائل غير مقروءة أو طلب محادثة وارد تُعرض كإشعار واحد فقط، دون كشف نصوص الرسائل في الجرس.
- تنشئ منظومة الرسائل القديمة أيضًا `account_notifications` من النوع `system` ورابط يبدأ بـ`/messages`. يستبعدها API الموحد من المصدر الأول كي لا يظهر نفس الحدث مرتين. عداد الجرس يحتسب محادثة واحدة بدل احتساب كل رسالة منفردة، بينما عداد الرسائل المستقل يحتفظ بسلوكه القديم.

## الصلاحيات والأمان

يستخدم API عميل Supabase مع مفتاح المتصفح وBearer الموثوق ويستدعي `authorizeAudience` للتحقق من الجلسة والأصل. الجداول تُقرأ عبر RLS؛ تحديث القراءة يغير حقل `read_at` فقط مع شرط `user_id`. لا تُمنح أدوار المتصفح صلاحيات جديدة.

بيانات محادثات الرسائل تتطلب `serverDb()` ودالة `private_messaging_inbox` الخدمية بعد التحقق من `user.id` الحقيقي والبريد المؤكد والحظر والتعليق. لا يقبل الخادم هويات من واجهة المستخدم، ولا يعيد نص رسائل خاصة إلى مركز الإشعارات.

تُقبل روابط محلية آمنة فقط، وتُرفض الروابط الخارجية على هيئة `//` أو المحتوية على محارف تحكم. تتضمن استجابات API ترويسات `no-store` و`noindex`.
