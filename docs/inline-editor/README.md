# التحرير المباشر — 967

هذه طبقة إضافية لإدارة المحتوى من الصفحات العامة، وتبقى لوحة التحرير الحالية ومركز المهام هما نظام الإدارة نفسه. التنفيذ على فرع `feat/inline-editor`، ولم يُنشر أو يُطبّق SQL على الإنتاج.

## التشغيل

1. سجّل الدخول بالحساب الإداري الحالي من `/admin` أو تسجيل الدخول المعتاد. يعتمد الدور على جدول `editors` وSupabase Auth القائمين.
2. افتح صفحة عامة، ثم اختر «تفعيل وضع التحرير». لا تظهر أدوات الإدارة قبل تحقق الخادم من الدور. يُحفظ التفضيل للحساب والجهاز فقط.
3. استخدم «تعديل الصفحة الحالية» أو قائمة `⋯` بجانب العنصر. يفتح زر المراجعة المشاركات الخاصة بالمناظرة الحالية، مع إمكانية عرض جميع المناظرات.
4. تتطلب القرارات الإشرافية سبباً. يعرض الحفظ الناجح رسالة، وخيار «تراجع» للإخفاء القابل للاستعادة. لا يُستعاد محتوى تغيّر بعد الإجراء.
5. يفتح «المحرر الكامل» العنصر نفسه في اللوحة الحالية. إنشاء مهمة يتطلب حفظ النموذج صراحةً، وتظهر المهمة في مركز المهام الحالي مع رابط مصدرها.

على الهاتف يُفتح الشريط من زر صغير. تدعم النوافذ Escape وإعادة التركيز وتحذير التعديلات غير المحفوظة. يزيل تسجيل الخروج الأدوات، وتُرفض الإجراءات بعد سحب الدور حتى إذا بقي تفضيل محلي قديم.

## قاعدة البيانات

الحفظ الجديد يحتاج إلى [202610210001_inline_editor.sql](../../supabase/migrations/202610210001_inline_editor.sql). الملف معاملة واحدة ويُطبّق مرة واحدة بعد مخطط المشروع والأدوار ومركز المهام وتحديثات المناظرات الثلاثة السابقة. **لا تنفذه على مشروع الإنتاج أثناء الاختبار.**

ترتيب التجهيز في مشروع Supabase اختباري مستقل:

1. تحقق من تثبيت مخطط الموقع والأدوار ومركز المهام ومخططات الأقسام المستخدمة. يجب وجود جداول المحتوى قبل migration حتى تُضاف إليها مشغلات النسخ والتدقيق.
2. طبّق تحديثات المناظرات `202610200001_debates.sql` ثم `202610200002_debates_review_fixes.sql` ثم `202610200003_debates_live_results.sql` إذا لم تكن مطبقة مسبقاً.
3. راجع وطبّق `202610210001_inline_editor.sql` من SQL Editor. لا يعيد التطبيق إنشاء الحسابات أو تغيير إعدادات Auth.
4. إذا كانت تعريفات أماكن الخريطة ناقصة، راجع وطبّق [yemen-map-profile-seed.sql](../../supabase/yemen-map-profile-seed.sql) بعد مخطط الخريطة والتحديث. يضيف التعريفات الناقصة فقط، دون استبدال الأوصاف والأرقام القائمة.
5. جرّب زائراً وحساب مستخدم وAdmin وManagement قبل نقل التحديث لأي بيئة منشورة.

يتطلب استيراد الشخصيات الاختياري `--apply` الآن `EDITOR_ACTOR_ID` لمعرّف المسؤول الفعلي، إلى جانب إعدادات الخدمة الموجودة، لتوثيق الحفظ والتحقق من دوره. وضع المعاينة لا يستورد بيانات.

## التحقق المحلي المعزول

لا يحمل مزود الاختبار `.env.local` ولا يتصل بقاعدة إنتاج. شغّل الجلسة الأولى:

```powershell
node scripts/inline-editor-preview-fixture.mjs
```

الجلسة الثانية تستخدم إعدادات خاصة بالعملية فقط:

```powershell
$env:NEXT_PUBLIC_SUPABASE_URL='http://127.0.0.1:3417'
$env:NEXT_PUBLIC_SUPABASE_ANON_KEY='local-fixture-anon'
$env:SUPABASE_SERVICE_ROLE_KEY='local-fixture-service'
$env:NEXT_TASK_PREVIEW='1'
node node_modules/next/dist/bin/next dev --hostname 127.0.0.1 --port 3117
```

ثم شغّل من جلسة ثالثة:

```powershell
npm.cmd test
npm.cmd run lint
node scripts/test-inline-editor-browser.mjs
```

اختبار المتصفح يستخدم Chromium وPlaywright وaxe الموجودين ضمن أدوات المشروع المحلية؛ يمكن تعيين `AUDIT_CHROME_PATH` لمسار Chromium. أعد تشغيل مزود الاختبار قبل إعادة الرحلة الكاملة لاسترجاع البيانات الأولية، وأوقف الخادمين بعد التحقق. لا تغيّر ملفات الواجهة أثناء الرحلة، لأن التحديث التلقائي لخادم التطوير قد يعيد تركيب النماذج.

لبناء التحقق في مجلد مستقل ومقارنة تكلفة JavaScript:

```powershell
$env:NEXT_VALIDATION_BUILD='1'
npm.cmd run build
node scripts/compare-inline-editor-guest-js.mjs
```

مرجع المقارنة محفوظ من بناء `main` السابق قبل إضافة الميزة. يتضمن القياس JavaScript الأولي للمسار؛ أرقام gzip تقديرية لضغط كل ملف، وليست قياس نقل الشبكة.
