# تقرير تسليم مركز مهام 967

التاريخ: 19 أكتوبر 2026. الفرع: `feat/967-task-center`.

**الحالة: التنفيذ المحلي مكتمل ومختبر على PostgreSQL معزول. لم يُطبّق Migration على الإنتاج، ولم يُنشر الموقع. اعتماد جاهزية الإنتاج يتطلب اختبار Supabase الاختباري متعدد الاتصالات قبل التفعيل.**

## ما أُنجز

مركز داخلي على `/admin/tasks` متصل بنفس تسجيل الدخول والأدوار الحالية، مع رابط وبطاقة ملخص مستقلة التحميل داخل `/admin`. يدعم إنشاء المهام وتعديلها وبدءها وإكمالها وإعادة فتحها والمراجعة الاختيارية، المواعيد الكاملة أو ذات الساعة، الأولويات والوسوم والروابط، الخطوات ونسب الإنجاز، القائمة وKanban بالسحب والإفلات والتقويم الشهري والأسبوعي، الفلاتر المحفوظة في URL، التعليقات وسجل التدقيق، التنبيهات، التكرار عند الإكمال، التقارير الأسبوعية، والأرشفة والاستعادة والحذف المنطقي للإدارة.

يقرأ كل Admin وManagement مهام الفريق كاملة. يُحظر تعديل مهام الآخرين على الأدمن، ويُحظر تجاوز الصلاحيات في API وRLS والحقول والدوال. لا تُعطى للمتصفح صلاحيات Service Role ولا يُوسّع الوصول إلى جدول المستخدمين الحالي.

## قاعدة البيانات

Migration تنشئ الجداول الستة `tasks`، `task_projects`، `task_subtasks`، `task_comments`، `task_activity`، `task_notifications`، مع المفاتيح الخارجية والفهارس وسياسات SELECT/INSERT/UPDATE/DELETE المسموح بها لكل دور. التكرار مخزن في حقلي `recurrence` و`recurrence_of` مع قيد فريد يمنع ازدواج النسخة التالية.

تتحكم Triggers في هوية وتوقيت الإكمال، الصلاحيات والحقول الثابتة، توثيق التعديلات، تنبيهات الأحداث، وإنشاء النسخة التالية مع خطوات غير مكتملة. الدوال `task_role` و`task_can_edit` و`task_visible` و`task_team` تتحقق من الفريق دون تغيير سياسات `editors` القديمة. `task_mutate` يحتفظ بامتيازات المستخدم، مع قفل ونسخة متزايدة لكل مهمة، ومساعدي قفل وحذف ضيقي النطاق.

ترتيب التثبيت ومتغيرات البيئة وتفاصيل السياسات موثقة في [دليل التثبيت والاستخدام](README_AR.md). لا حاجة إلى أسرار جديدة أو Cron أو Storage في الإصدار الحالي. SQL يُراجع ويُطبق مرة واحدة على مشروع اختباري أولاً، ثم على الإنتاج فقط بعد موافقة صريحة منفصلة.

## حدود التحقق والخطوات المتبقية

1. **لم يُختبر تثبيت فعلي على Supabase/PostgREST أو جلسات Auth حقيقية مخصصة لهذه الميزة.** SQL والسياسات شُغّلت على محرك PostgreSQL حقيقي معزول بواسطة PGlite؛ المصادقة في بيئة الاختبار بديل محلي. اتبع خطوات التحقق بـAdmin A وAdmin B وManagement C والمستخدم غير المعتمد في الدليل على مشروع اختبار منفصل.
2. **لم يُختبر تنافس اتصالات PostgreSQL مستقلة عبر الشبكة.** PGlite يستخدم اتصالاً واحداً. اختبارات الطلبات المتنافسة تثبت سلوك النسخة والقيد الفريد في هذا المحرك، وتبقى جولة جلستين فعليتين على Supabase مطلوبة، خصوصاً مع إعادة الإسناد أو إزالة صلاحية عضو بالتزامن.
3. **لا يوجد نشر أو Migration إنتاجي.** الملفات جاهزة للمراجعة والتجربة، ويجب اجتياز فحص Supabase السابق قبل وصف النظام بأنه جاهز للإنتاج.
4. التذكيرات الزمنية تُنشأ عند فتح المركز؛ التكرار عند الإكمال. لا إرسال بريد ولا جدولة خارج الموقع. إذا أضيفت خدمة Cron مستقبلاً، يلزم إعدادها وحمايتها واختبارها منفصلة.
5. رفع المرفقات غير مفعّل؛ الروابط مدعومة. يتطلب رفع الملفات إعداد تخزين خاص وصلاحيات وروابط مؤقتة منفصلة.
6. صفحات النتائج تُرسل مقسمة، بينما المؤشرات والبحث يجمعان بيانات الفريق على الخادم على دفعات. حجم بيانات أكبر بكثير يستدعي نقل التجميع والبحث إلى استعلامات SQL مخصصة.

خطوات التحقق والأدوار وإعداد المعاينة وإعادة تشغيل الاختبارات متاحة كاملة في [README العربي](README_AR.md).
