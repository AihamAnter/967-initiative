## الأرشفة التلقائية

تُحدد الأرشفة بعد **24 ساعة فعلية** من الإكمال، وليس عند تغير التاريخ المحلي. الترحيل يفعّل `pg_cron` عندما يكون متاحاً، وينشئ مهمة `967-task-auto-archive` كل خمس دقائق. بالتالي تتم الأرشفة في أول دورة بعد انقضاء الساعات الأربع والعشرين، حتى عندما لا تكون اللوحة مفتوحة. توجد أيضاً صيانة عند قراءة مركز المهام، وتحديث كل دقيقة أثناء فتحه.

تحقق من وجود المهمة وتشغيلها بعد تطبيق الترحيل:

```sql
select jobid, jobname, schedule, active
from cron.job
where jobname = '967-task-auto-archive';

select status, start_time, end_time, return_message
from cron.job_run_details
where jobid in (
  select jobid from cron.job where jobname = '967-task-auto-archive'
)
order by start_time desc
limit 10;
```

إن لم يدعم الخادم `pg_cron`، تعمل الصيانة عند فتح المركز وتحديثه فقط؛ يحتاج التنفيذ المستقل إلى مجدول معتمد على الخادم. يمكن تمكين Cron من واجهة Supabase أيضاً وفق [تعليمات التثبيت الرسمية](https://supabase.com/docs/guides/cron/install).

تبقى المهمة في الأرشيف مع سجلها. الاستعادة تمنحها 24 ساعة جديدة، وإعادة فتحها تلغي موعد الأرشفة. الأرشفة التلقائية لا تنشئ نسخة متكررة ثانية ولا تمحو إكمالها من إحصاءات الأسبوع. أعمال النظام موسومة بوضوح في سجل النشاط.
